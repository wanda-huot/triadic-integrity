# The Triadic Integrity Framework

**Status:** Working draft  
**Author:** Gwendolyn Huot  
**Project umbrella:** Framecraft  
**Purpose:** A working repository for developing, testing, and expressing The Triadic Integrity Framework.

---

## Overview

The Triadic Integrity Framework is a working model for describing how experience, action, and meaning become coherent.

At its simplest, the framework asks:

- What is trying to happen?
- What can the system actually hold?
- What needs to be adjusted so the whole thing works?

The framework is organized around a triadic pattern:

1. **Forces** — what generates movement, salience, pressure, desire, or direction.
2. **Capacities** — what can hold, support, limit, structure, or bear those forces.
3. **Operations** — what the system can do to adjust, adapt, respond, and form coherence over time.

The goal is not to create a closed theory of everything. The goal is to build a practical, disciplined grammar for noticing patterns in lived experience, work, relationships, creative practice, self-regulation, and meaning-making.

---

## Current status

This repository is an early working draft.

It is being developed in Markdown so that the framework can be:

- read by humans,
- reused by AI agents,
- tested through examples,
- revised over time,
- and eventually expressed in other formats such as websites, printable PDFs, diagrams, structured data, agent prompts, and physical models.

Some files are more canonical. Others are exploratory. The framework should be treated as a live project under active development.

---

## What this framework is for

The Triadic Integrity Framework is meant to help with:

- diagnosing stuckness without reducing it to one cause,
- distinguishing forces, capacities, and adaptive operations,
- mapping self-help, therapeutic, philosophical, and practical frameworks by function,
- creating clearer prompts for AI-assisted reflection,
- building human-facing registers that translate the same deep structure into different domains,
- creating bridge documents that compare the framework with external systems,
- and testing whether a simple triadic grammar can support practical insight.

It is not a clinical tool, a spiritual doctrine, a personality system, a scientific theory, or a replacement for existing human expertise.

The framework should be judged by use:

- Does it clarify a situation?
- Does it reveal a useful distinction?
- Does it suggest a better next move?
- Does it help humans or agents reason more clearly?

## Intellectual background

The framework has some loose resonance with triadic traditions of thought, including Peircean themes such as quality, encounter, and continuity.

That resemblance is useful background context, not a formal derivation.

This is not a Peirce scholarship project, and the framework does not depend on Peirce for its validity.

## Core architecture

The framework is organized into three articulation layers.

---

### Layer 0: The Structural Layer

Layer 0 names the most basic structural primitives:

- **Quality** — felt salience, tone, vividness, character.
- **Contact** — encounter, friction, reality, relation.
- **Continuity** — pattern, persistence, form, recognizability.

These primitives form dyads, and the dyads generate a field of possible triadic coherence.

Layer 0 is abstract, descriptive, and non-diagnostic.

---

### Layer 1: The Mechanical Layer

Layer 1 translates the structural primitives into a more mechanical ontology.

It currently contains three main systems:

- **The Three Forces** — what generates movement or directional pressure.
- **The Three Capacities** — what can hold, support, limit, or bear that pressure.
- **The Three Operations** — what the system can do to adapt, adjust, and stabilize.

Layer 1 is the main diagnostic layer of the framework.

Its core diagnostic states are:

- **Slack** — under-formed, under-powered, vague, loose, or insufficiently connected.
- **Tight** — over-constrained, pressured, brittle, rigid, or over-controlled.
- **Misdirected** — skewed, misaligned, wrongly aimed, or distorted in orientation.
- **Coherent Formation** — the well-formed condition in which the system holds together responsively.

---

### Layer 2: Human Registers

Layer 2 translates the framework into human-facing language.

A register is a way of speaking the framework for a particular audience, use case, or domain.

Current and emerging registers include:

- **The Three Pulls Register** — the original formative human-facing version of the framework.
- **The Working Register** — for work, projects, effort, burnout, and practical prioritization.
- **The Embodied Register** — for felt experience, self-regulation, affect, and bodily awareness.
- **The Kid Register** — for child-friendly emotional and practical language.
- **Additional proposed registers** — for relational, narrative, cognitive, creative, spiritual, caregiving, family-system, and other domains.

Registers are translations, not separate frameworks.

---

## Bridges

Bridges are comparative translation documents.

They connect The Triadic Integrity Framework with external frameworks, theories, traditions, modalities, or vocabularies.

A Bridge asks:

```text
How does The Triadic Integrity Framework relate to another system?
```

Bridges are not Human Registers.

Human Registers translate the framework into usable language for a domain, audience, or situation.

Bridges compare the framework with an external system and identify:

- useful resonances,
- possible translations,
- mismatches,
- limits,
- and cautions against overclaiming.

Possible future Bridges include:

- Peirce
- active inference
- 4E cognition
- ACT
- IFS
- Self-Determination Theory
- relevance realization

---

## Expression Formats

Expression Formats are the forms the framework can take so it can be stored, displayed, taught, navigated, reused, or executed.

Examples include:

- a GitHub Markdown repository,
- printable PDFs,
- diagrams,
- structured data files,
- a public website,
- agent prompts,
- interactive tools,
- and physical models.

Key distinction:

```text
Human Registers = how the framework speaks.
Bridges = how the framework compares and translates across systems.
Expression Formats = how the framework appears, circulates, and operates.
```

## Where to start

For a human reader:

1. Start with this README.
2. Read `QUICK-REFERENCE.md`.
3. Read `framework/layer-0-structural-layer.md`.
4. Read `framework/layer-1-mechanical-layer.md`.
5. Read one register, probably `registers/three-pulls-register.md` or `registers/working-register.md`.
6. Read `bridges/README.md` if interested in how the framework may compare with external systems.
7. Read `expression-formats/README.md` if interested in the forms the framework may take.

For an AI agent:

1. Start with `AGENT-START-HERE.md`.
2. Use `CONVENTIONS.md` as the naming and formatting authority.
3. Use `GLOSSARY.md` for term definitions.
4. Use the framework files as the canonical structure.
5. Treat register files as translation layers.
6. Treat Bridge files as comparative translation documents.
7. Treat Expression Format files as documentation of the forms the framework can take.

## Development priorities

The next priority is not to add many more registers or bridges.

The next priority is to make the existing framework easier to test.

Near-term priorities:

1. Clean and stabilize the core terminology.
2. Maintain a concise glossary.
3. Add worked examples.
4. Demonstrate the diagnostic layer with real cases.
5. Develop one human-facing register more deeply.
6. Create a minimal Wanda agent prompt or specification.
7. Use examples to test whether the distinctions actually help.

The framework should grow vertically before it grows horizontally.

---

## Design cautions

This project should avoid:

- excessive symbol density in human-facing materials,
- premature claims of scientific or philosophical authority,
- adding more registers before existing ones are tested,
- adding bridge documents before there is enough care to compare honestly,
- treating AI-generated coherence as proof of usefulness,
- and mistaking elegant structure for demonstrated value.

The framework should remain practical, revisable, and testable.
