# The Triadic Integrity Framework

Status: Working draft  
Author: Gwendolyn Huot  
Project umbrella: Framecraft  
Purpose: A working repository for developing, testing, and expressing The Triadic Integrity Framework.

---

## Overview

The Triadic Integrity Framework, aka Tri Everything, is a working model for describing how experience, action, and meaning become coherent.

At its simplest, the framework asks:

- What is trying to happen?
- What can the system actually hold?
- What needs to be adjusted so the whole thing works?

The framework is organized around a triadic pattern:

1. Forces — what generates movement, salience, pressure, desire, or direction.
2. Capacities — what can hold, support, limit, structure, or bear those forces.
3. Operations — what the system can do to adjust, adapt, respond, and form coherence over time.

The goal is not to create a closed theory of everything.

The goal is to build a practical, disciplined grammar for noticing patterns in lived experience, work, relationships, creative practice, self-regulation, and meaning-making.

---

## Current status

This repository is an early working draft.

It is being developed in Markdown so that the framework can be:

- read by humans,
- reused by AI agents,
- tested through examples,
- revised over time,
- and expressed in other formats such as websites, printable PDFs, diagrams, structured data, agent prompts, and physical models.

Some files are more canonical. Others are exploratory.

The framework should be treated as a live project under active development.

---

## What this framework is for

The Triadic Integrity Framework is meant to help with:

- diagnosing stuckness without reducing it to one cause,
- distinguishing forces, capacities, and adaptive operations,
- mapping self-help, therapeutic, philosophical, and practical frameworks by function,
- comparing the framework carefully with external systems without collapsing them into one another,
- creating clearer prompts for AI-assisted reflection,
- building human-facing registers that translate the same deep structure into different domains,
- and testing whether a simple triadic grammar can support practical insight.

It is not a clinical tool, a spiritual doctrine, a personality system, a scientific theory, or a replacement for existing human expertise.

The framework should be judged by use:

- Does it clarify a situation?
- Does it reveal a useful distinction?
- Does it suggest a better next move?
- Does it help humans or agents reason more clearly?

## Intellectual background

The framework has loose resonance with triadic traditions of thought, including Peircean themes such as quality, contact, and continuity.

That resemblance is useful background context, not a formal derivation.

This is not a Peirce scholarship project, and the framework does not depend on Peirce for its validity.

## Core architecture

The framework is organized into three articulation layers.

---

### Layer 0: The Structural Layer

Layer 0 names the most basic structural primitives:

- Quality — felt salience, tone, vividness, character.
- Contact — encounter, friction, reality, relation.
- Continuity — pattern, persistence, form, recognizability.

These primitives form dyads, and the dyads generate a field of possible triadic coherence.

Layer 0 is abstract, descriptive, and non-diagnostic.

---

### Layer 1: The Mechanical Layer

Layer 1 translates the structural primitives into a more mechanical ontology.

It currently contains three main systems:

- The Three Forces — what generates movement or directional pressure.
- The Three Capacities — what can hold, support, limit, or bear that pressure.
- The Three Operations — what the system can do to adapt, adjust, and stabilize.

Layer 1 is the main diagnostic layer of the framework.

Its core diagnostic states are:

- Slack — under-formed, under-powered, vague, loose, or insufficiently connected.
- Tight — over-constrained, pressured, brittle, rigid, or over-controlled.
- Misdirected — skewed, misaligned, wrongly aimed, or distorted in orientation.
- Coherent Formation — the well-formed condition in which the system holds together responsively.

Coherent Formation is not a fourth distortion. It is the well-formed condition that the diagnostic states help clarify by contrast.

---

### Layer 2: Recursive System Scales

Layer 2 situates the framework within recursive scales of organization.

It identifies the scale at which a pattern is operating — Agent, Relation, or Field — and attends to how those scales interact through their dyadic relations and emergent whole.

Layer 2 is structural, not applied. Human-facing translations belong to the Registers in the Applied Framework.

---

## Applied Framework

The Applied Framework is the practical and expressive work built on top of the Core Framework.

It contains four categories:

- **Registers** — how the framework speaks in different human domains.
- **Bridges** — how the framework compares and translates across external systems.
- **Expression Formats** — how the framework appears, circulates, and operates.
- **Tools** — how the framework is used for diagnosis, reflection, and action.

The Three Pulls Register is the original formative human-facing version of the framework, and lives in the Applied Framework.

---

## Applied Framework categories

**Registers** translate the framework into usable language for a particular audience, domain, or situation.

**Bridges** connect the framework with external frameworks, theories, traditions, modalities, or vocabularies — identifying resonances, mismatches, and limits without overclaiming equivalence.

**Expression Formats** are the forms the framework can take so it can be stored, displayed, taught, navigated, reused, or executed — GitHub Markdown, printable PDFs, diagrams, structured data, websites, agent prompts.

**Tools** are practical artifacts for diagnosis, reflection, decision-making, and action.

Key distinctions:

```text
Registers = how the framework speaks.
Bridges = how the framework compares and translates across systems.
Expression Formats = how the framework appears, circulates, and operates.
Tools = how the framework is used practically.
```

## Where to start

For a human reader:

1. Start with this README.
2. Read `QUICK-REFERENCE.md`.
3. Read `framework/layer-0-structural-layer.md`.
4. Read `framework/layer-1-mechanical-layer.md`.
5. Read `framework/layer-2-recursive-system-scales.md`.
6. Read one register, probably `registers/three-pulls-register.md` or `registers/working-register.md`.
6. Skim `bridges/README.md` if you want to understand how this framework may relate to outside systems.
7. Skim `expression-formats/README.md` if you want to understand how the framework may be packaged, displayed, or used.

For an AI agent:

1. Start with `AGENT-START-HERE.md`.
2. Use `CONVENTIONS.md` as the naming and formatting authority.
3. Use `GLOSSARY.md` for term definitions.
4. Use the framework files as the canonical structure.
5. Treat register files as translation layers.
6. Treat bridge files as comparisons with external systems.
7. Treat expression-format files as packaging, storage, display, or execution formats.

---

## Design cautions

This project should avoid:

- excessive symbol density in human-facing materials,
- premature claims of scientific or philosophical authority,
- treating AI-generated coherence as proof of usefulness,
- mistaking elegant structure for demonstrated value,
- and collapsing external systems into the framework too quickly.

The framework should remain practical, revisable, and testable.
