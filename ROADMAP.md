# ROADMAP

# Triadic Integrity Framework v2

The current public repository represents v1 of the Triadic Integrity Framework.

v1 successfully established:
- the Layer 0 Structural ontology,
- the Layer 1 Mechanical systems,
- diagnostic distortions,
- human registers,
- and practical applications for individual psychology and self-regulation.

However, v1 revealed several important limitations:
- interpersonal dynamics were difficult to model cleanly,
- larger social systems tended to be treated as extensions of individual psychology,
- Human Registers occupied an ambiguous position in the architecture,
- and recursive/multi-scale dynamics were underdeveloped.

v2 is an attempt to address these limitations.

---

# Core Direction of v2

The central move of v2 is to treat the framework as a recursive systems architecture rather than primarily a framework for individual psychology.

The framework is increasingly understood as:
- a recursive grammar,
- a systems ontology,
- and a scale-flexible mechanical architecture
capable of modeling:
- persons,
- relationships,
- groups,
- institutions,
- cultures,
- and distributed human–AI systems.

---

# Structural Changes in v2

## Core Framework

v2 reorganizes the framework into three core layers:

### Layer 0: Structural

The minimal triadic ontology:
- ★ Quality
- ● Contact
- ■ Continuity

This layer describes the primitive structural relations underlying the framework.

---

### Layer 1: Mechanical

The recursive mechanics derived from Layer 0 variation:
- forces,
- capacities,
- operations,
- distortions,
- and coherent formations.

Layer 1 treats these as scale-flexible system mechanics rather than merely internal psychological structures.

---

### Layer 2: Recursive System Scales

Layer 2 models how triadic systems recursively emerge across scales.

This includes:
- ○ Agent Scale
- ○ Relation Scale
- ○ Field Scale
- ⟷ Agent–Relation Scale
- ⟷ Relation–Field Scale
- ⟷ Agent–Field Scale
- △ Recursive System Ecology

Core principle:

> agents form relations; relations generate fields; fields shape agents.

This layer aims to support:
- interpersonal dynamics,
- distributed cognition,
- organizational systems,
- cultural emergence,
- ecological thinking,
- and human–AI coordination systems.

# Major Open Questions

v2 remains exploratory.

Open questions include:
- how recursive mechanics should formally propagate across scales,
- whether Layer 1 systems themselves recursively instantiate Layer 0 structure,
- how fields and institutions should be modeled,
- how to prevent recursive abstraction from becoming vague or non-operational,
- and how AI agents should ingest and apply the framework.

Another major open question:
- how much mathematical, cybernetic, or systems-theoretic formalization the framework ultimately requires.

---

# Design Goals

v2 aims to preserve the strengths of v1:
- clarity,
- compactness,
- symbolic discipline,
- practical usability,
- and AI-native structure,

while expanding the framework toward:
- recursive systems thinking,
- multi-agent dynamics,
- distributed cognition,
- and ecological/interpersonal modeling.

---

# Guiding Constraint

The framework should remain:
- mechanically legible,
- operationally useful,
- and human-usable.

Recursive elegance should not come at the cost of practical clarity.

The goal is not:
"everything is triadic."

The goal is:
to identify where triadic recursive structures genuinely improve explanation, diagnosis, coordination, and action.

# Repository Structure

v2 separates the repository into two major zones:

## Core Framework

The Core Framework describes what the framework *is*.

This includes:
- the structural ontology,
- recursive mechanics,
- and recursive system scales.

Proposed structure:

```text
core-framework/
├─ README.md
├─ layer-0-structural.md
├─ layer-1-mechanical.md
└─ layer-2-recursive-system-scales.md
```

The Core Framework is intended to remain:
- compact,
- disciplined,
- recursive,
- and relatively stable.

---

## Applied Framework

The Applied Framework describes how the framework is:
- translated,
- compared,
- represented,
- and used.

Proposed structure:

```text
applied-framework/
├─ registers/
├─ bridges/
├─ formats/
└─ tools/
```

These categories serve different functions:

| Category | Purpose |
|---|---|
| Registers | How the framework speaks in different human domains. |
| Bridges | How the framework relates to other frameworks and traditions. |
| Formats | How the framework is represented, displayed, or deployed. |
| Tools | How the framework is practically used. |

This separation is intended to prevent:
- ontological confusion,
- category collapse,
- and the tendency for practical applications to become mixed with core mechanics.

The distinction can be summarized simply:

> The Core Framework describes the recursive architecture itself.  
> The Applied Framework describes how humans and systems interact with it.

This is an important conceptual clarification for v2. In v1, many concepts that were actually:
- translations,
- interfaces,
- or applications

were implicitly treated as ontological layers.

The new repository structure corrects that.
