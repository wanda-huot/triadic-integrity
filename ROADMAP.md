# ROADMAP

# Triadic Integrity Framework v2

The current public repository represents **v1** of the Triadic Integrity Framework.

v1 successfully established:
- the Layer 0 Structural ontology,
- the Layer 1 Mechanical systems,
- diagnostic distortions,
- human registers,
- and practical applications for individual psychology and self-regulation.

v2 develops the framework in a more explicitly recursive and systems-oriented direction.

The central shift is this:

> v1 primarily models individual psychology and practical self-regulation.  
> v2 expands the framework into a recursive systems architecture capable of modeling agents, relations, fields, and multi-scale emergence.

---

# Why v2?

v1 revealed several important limitations:
- interpersonal dynamics were difficult to model cleanly,
- larger social systems tended to be treated as extensions of individual psychology,
- Human Registers occupied an ambiguous position in the architecture,
- and recursive or multi-scale dynamics were underdeveloped.

v2 addresses these limitations by separating the framework into two major zones:

1. **Core Framework** — what the framework is.
2. **Applied Framework** — how the framework is translated, expressed, compared, and used.

This separation is intended to prevent category confusion between:
- ontology,
- mechanics,
- scale,
- translation,
- representation,
- comparison,
- and practice.

---

# Core Direction of v2

The framework is increasingly understood as:
- a recursive grammar,
- a systems ontology,
- and a scale-flexible mechanical architecture.

v2 aims to model:
- persons,
- relationships,
- groups,
- institutions,
- cultures,
- ecologies,
- and distributed human–AI systems.

The goal is not to claim that everything is triadic.

The goal is to identify where triadic recursive structures genuinely improve:
- explanation,
- diagnosis,
- coordination,
- and action.

# Core Framework

The **Core Framework** describes the recursive architecture itself.

It includes:
- the structural ontology,
- recursive mechanics,
- and recursive system scales.

The Core Framework is intended to remain:
- compact,
- disciplined,
- recursive,
- and relatively stable.

---

## Layer 0: Structural

Layer 0 defines the minimal triadic ontology:

- ★ Quality
- ● Contact
- ■ Continuity

Layer 0 describes the primitive structural terms and relations underlying the framework.

It asks:

> What are the irreducible primitives and relations?

---

## Layer 1: Mechanical

Layer 1 describes the recursive mechanics derived from Layer 0 variation.

It includes:
- forces,
- capacities,
- operations,
- distortions,
- and coherent formations.

Layer 1 treats these as scale-flexible system mechanics rather than merely internal psychological structures.

It asks:

> How does the triadic structure work mechanically?

---

## Layer 2: Recursive System Scales

Layer 2 describes how triadic systems recur across scales.

It includes:

- ○ Agent Scale
- ○ Relation Scale
- ○ Field Scale
- ⟷ Agent–Relation Scale
- ⟷ Relation–Field Scale
- ⟷ Agent–Field Scale
- △ Recursive System Ecology

Core principle:

> agents form relations; relations generate fields; fields shape agents.

Layer 2 aims to support:
- interpersonal dynamics,
- distributed cognition,
- organizational systems,
- cultural emergence,
- ecological thinking,
- and human–AI coordination systems.

It asks:

> Where, and at what scales, do these mechanics recur?

---

# Applied Framework

The **Applied Framework** describes how the framework is:
- translated,
- compared,
- represented,
- and used.

In v2, applied materials are separated from the core ontological stack.

This corrects a major ambiguity in v1: many concepts that were actually translations, interfaces, or applications were implicitly treated as ontological layers.

The Applied Framework currently includes four categories:

| Category | Purpose |
|---|---|
| Registers | How the framework speaks in different human domains. |
| Bridges | How the framework relates to other frameworks, theories, traditions, or modalities. |
| Formats | How the framework is represented, stored, displayed, circulated, or deployed. |
| Tools | How the framework is used for diagnosis, reflection, decision-making, practice, and action. |

---

## Registers

Registers are domain-specific or audience-specific ways the framework speaks.

Examples:
- The Three Pulls Register
- Embodied Register
- Working Register
- Kid Register
- Narrative Register
- Relational Register

Registers are not numbered layers in v2. They are applied translations.

---

## Bridges

Bridges connect the framework to external frameworks, theories, traditions, or modalities.

Potential bridge targets include:
- Peirce,
- Bateson,
- Taoism,
- Active Inference,
- 4E Cognition,
- IFS,
- ACT,
- cybernetics,
- and systems theory.

Bridges should identify:
- resonances,
- mismatches,
- limits,
- useful translations,
- and places where comparison breaks down.

---

## Formats

Formats describe how the framework is represented, stored, displayed, circulated, or deployed.

Examples:
- GitHub Markdown,
- diagrams,
- printable PDFs,
- AI agents,
- physical models,
- websites,
- structured data files.

Formats are not the framework itself. They are expression forms.

---

## Tools

Tools describe how the framework is practically used.

Examples:
- diagnostic matrices,
- reflection prompts,
- decision workflows,
- conversational scaffolds,
- intervention tools,
- practice guides,
- and AI-agent procedures.

Tools should remain operational rather than merely descriptive.

---

# Major Open Questions

v2 remains exploratory.

Open questions include:
- how recursive mechanics should formally propagate across scales,
- whether Layer 1 systems themselves recursively instantiate Layer 0 structure,
- how fields, institutions, and cultures should be modeled,
- how to prevent recursive abstraction from becoming vague or non-operational,
- how AI agents should ingest and apply the framework,
- and how much mathematical, cybernetic, or systems-theoretic formalization the framework ultimately requires.

A practical test for v2:

> Does the recursive architecture help explain something that v1 could only describe awkwardly?

---

# Design Goals

v2 aims to preserve the strengths of v1:
- clarity,
- compactness,
- symbolic discipline,
- practical usability,
- and AI-native structure,

while expanding the framework toward:
- recursive systems thinking,
- multi-agent dynamics,
- distributed cognition,
- ecological modeling,
- interpersonal modeling,
- and human–AI coordination.

---

# Guiding Constraints

The framework should remain:
- mechanically legible,
- operationally useful,
- human-usable,
- and AI-ingestible.

Recursive elegance should not come at the cost of practical clarity.

The framework should avoid:
- vague universalism,
- decorative symbolism,
- excessive abstraction,
- category collapse,
- and claims that cannot be operationalized.

A useful constraint:

> If the framework cannot help someone notice, compare, decide, repair, coordinate, or act, it has become too abstract.

The Core/Applied distinction is documented throughout the root files and CONVENTIONS without requiring a directory reorganization. This avoids breaking existing paths and keeps the structure navigable.

Revisit the directory reorganization only if the repository grows to a scale where the current structure becomes confusing.

- Why it is relevant to Triadic Integrity v2
- Resonances
- Mismatches

- Cautions / non-claims

Do not claim equivalence or derivation.

# Long-Term Direction

The long-term direction is to develop the Triadic Integrity Framework into a recursive, AI-native grammar for sensemaking across scales.

This means supporting:
- individual reflection,
- interpersonal repair,
- group coordination,
- institutional analysis,
- cultural diagnosis,
- framework comparison,
- and AI-assisted practical reasoning.

v2 should make the framework more capable of moving between:
- lived experience,
- structural diagnosis,
- system-scale analysis,
- practical intervention,
- and comparison with other sensemaking traditions.

The intended result is not a finished grand theory.

The intended result is a disciplined, recursive grammar that can keep improving through use.
