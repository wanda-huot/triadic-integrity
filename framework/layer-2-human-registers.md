## 1. Extended description

**Layer 2: The Human Registers Layer** translates the Triadic Integrity Framework into usable human language.

Where **Layer 0: The Structural Layer** defines the core metaphysical grammar of **★ Quality**, **● Contact**, and **■ Continuity**, and **Layer 1: The Mechanical Layer** translates that structure into **⟶ The Three Forces**, **⬡ The Three Capacities**, and **↻ The Three Operations**, Layer 2 asks:

> How can this structure be spoken in a way that is useful to a particular person, audience, domain, or situation?

Layer 2 contains **Human Registers**.

A Human Register is not a separate framework. It is a translation layer. It gives the same underlying structure a different vocabulary, tone, metaphor, and practical emphasis.

Examples include:

- **The Three Pulls Register**
- **The Kid Register**
- **The Working Register**
- **The Embodied Register**
- **The Christian Theological Register**
- proposed future registers such as relational, narrative, cognitive, creative-practice, caregiving, grief, or community registers

Layer 2 is where the framework becomes easier to use in ordinary life. It allows the same structure to speak differently to a child, a working adult, an artist, a parent, an AI agent, a spiritual reader, or someone noticing body signals.

The governing rule is:

> Human Registers are different translation layers of one underlying triadic structure.

---

## 2. Purpose

Layer 2 exists because technically accurate language is not always the most useful language.

The canonical Layer 1 term **⟶○★ Qualitative Force** is precise, but it may not be the best phrase for ordinary reflection.

Depending on the context, the same structure may be better expressed as:

- Aliveness
- Bright Tug
- Charge
- Stakes
- Felt salience
- What has energy
- What is calling for attention

Layer 2 allows the framework to remain structurally disciplined while becoming humanly usable.

Layer 2 is useful for:

- practical decision-making
- self-reflection
- parenting
- teaching
- work and project planning
- embodied awareness
- spiritual or theological interpretation
- AI-agent interaction
- translating abstract structure into ordinary language

## 3. Relationship to Layer 0

Layer 0 defines the structural primitives:

- **★ Quality**
- **● Contact**
- **■ Continuity**

Layer 2 registers should remain traceable back to these primitives.

A register may use different words, but the structural roots should remain visible.

| Layer 0 primitive | General meaning | Possible Layer 2 translations |
|---|---|---|
| **★ Quality** | Felt salience, vividness, tone, qualitative character | aliveness, charge, brightness, stakes, feeling, spark |
| **● Contact** | Encounter, resistance, relation, friction, reality-contact | pressure, facing, coordination, support, asking, meeting reality |
| **■ Continuity** | Pattern, persistence, form, habit, recognizable structure | steadiness, holding pattern, rhythm, standard, routine, tradition |

Layer 2 should not invent new fundamentals.

It should translate the existing structure.

---

## 4. Relationship to Layer 1

Layer 1 defines the canonical mechanical systems:

- **⟶ The Three Forces**
- **⬡ The Three Capacities**
- **↻ The Three Operations**

Layer 2 translates these systems into more intuitive, domain-specific, or audience-specific terms.

| Canonical Layer 1 system | General function | Possible Layer 2 translations |
|---|---|---|
| **⟶ The Three Forces** | What generates movement | pulls, tugs, drives, demands, signals, energies |
| **⬡ The Three Capacities** | What the system can bear | room, bandwidth, support, cup, capacity, holding |
| **↻ The Three Operations** | What adaptive move is needed | moves, practices, adjustments, steering, next steps |

Layer 1 is the mechanical source.

Layer 2 is the human translation.

---

## 5. What makes a valid Human Register?

A Human Register is valid when it:

- translates the Layer 1 structure into a specific vocabulary
- remains traceable back to Layer 0 and Layer 1
- is useful for a real audience, domain, or use case
- clarifies rather than obscures the structure
- does not pretend to be a separate framework
- does not introduce new fundamentals without explanation
- does not overclaim clinical, spiritual, philosophical, or scientific authority

A Human Register should make the framework easier to use without losing the structure underneath.

---

## 6. What a Human Register is not

A Human Register is not:

- a new framework
- a personality system
- a clinical diagnostic system
- a spiritual authority
- a replacement for therapy, medicine, religion, or expert judgment
- a loose pile of metaphors
- a branding exercise detached from the underlying structure

Layer 2 can be poetic, practical, warm, playful, or domain-specific.

But it should remain structurally accountable.

## 8. The Three Pulls Register

**The Three Pulls Register** is the early, original, and formative language of the framework.

This is the language that helped the framework first become visible as a practical model: **Aliveness**, **Coordination**, and **Stability**, forming the **Wholesome Triangle**.

Later, the framework was refactored from **Layer 0: The Structural Layer** with the help of AI. That refactoring produced the more objective canonical Layer 1 language of **⟶ The Three Forces**, **⬡ The Three Capacities**, and **↻ The Three Operations**.

This means:

> **The Three Pulls** are not discarded. They are preserved as an important Layer 2 Human Register.

They remain valuable because they are intuitive, memorable, and practical.

They should not, however, be used as the canonical name for Layer 1 System 1.

Preferred mapping:

| Canonical Layer 1 term | Three Pulls Register |
|---|---|
| **⟶ The Three Forces** | The Three Pulls |
| **⟶○★ Qualitative Force** | Pull 1: Aliveness |
| **⟶○● Contact Force** | Pull 2: Coordination / Encounter |
| **⟶○■ Continuity Force** | Pull 3: Stability / Steadiness |
| **⟶△ Force Formation** | Wholesome Triangle |

Use this register when the goal is practical human reflection.

Use canonical Layer 1 language when the goal is structural precision.

## 9. The Kid Register

**The Kid Register** translates the framework into language that a child can use.

Its purpose is not to simplify the framework by removing the structure. Its purpose is to preserve the structure in language that is concrete, friendly, and emotionally usable.

Possible guiding questions:

- What is pulling on me?
- How much room do I have?
- What can I do next?

Possible mapping:

| Canonical Layer 1 system | Kid Register |
|---|---|
| **⟶ The Three Forces** | Tugs |
| **⬡ The Three Capacities** | Room / Cup |
| **↻ The Three Operations** | Inside Moves |

The Kid Register is useful for:

- emotional literacy
- parenting
- teaching
- conflict repair
- helping children name intensity without shame
- helping children find a next move

The Kid Register should be concrete, embodied, and low-abstraction.

## 10. The Working Register

**The Working Register** translates the framework into the domain of work, projects, and effort.

It is useful for:

- burnout
- prioritization
- stuck projects
- leadership
- creative blocks
- daily planning
- deciding what matters now
- finding a practical next move

Possible mapping:

| Canonical Layer 1 system | Working Register |
|---|---|
| **⟶ The Three Forces** | Demands |
| **⬡ The Three Capacities** | Bandwidth |
| **↻ The Three Operations** | Moves |

A Working Register version of the basic question might be:

```text
What is demanding attention?
What bandwidth is available?
What move would actually help?
```

The Working Register should be practical, concrete, and action-oriented.

## 11. The Embodied Register

**The Embodied Register** translates the framework into body-based and felt-sense language.

It is useful for noticing:

- body signals
- felt charge
- pressure
- bracing
- collapse
- steadiness
- tension
- orientation
- capacity
- settling

The Embodied Register is not a clinical or trauma-treatment model. It is a reflective body-awareness register.

Possible mapping:

| Canonical Layer 1 term | Embodied Register |
|---|---|
| **⟶ The Three Forces** | Body Signals |
| **⟶○★ Qualitative Force** | Charge |
| **⟶○● Contact Force** | Pressure |
| **⟶○■ Continuity Force** | Holding Pattern |
| **⬡ The Three Capacities** | Body Capacity |
| **⬡○★ Bodily/Regulatory Capacity** | Regulation Room |
| **⬡○● Social/Structural Capacity** | Supported Contact |
| **⬡○■ Form/Integrity Capacity** | Embodied Boundary |
| **↻ The Three Operations** | Body Moves |
| **↻○★ Explore Operation** | Notice |
| **↻○● Coordinate Operation** | Orient |
| **↻○■ Stabilize Operation** | Settle |

A simple Embodied Register check-in might ask:

```text
What is my body showing me?

```

The Embodied Register should avoid over-medicalizing ordinary experience.

It should support practical noticing, not diagnosis.

## 12. The Christian Theological Register

**The Christian Theological Register** translates the framework into Christian theological language.

It is a specialized Layer 2 register.

It may explore resonances with concepts such as:

- goodness
- glory
- incarnation
- encounter
- faithfulness
- tradition
- spiritual practice
- formation
- discernment
- communion

This register should be written carefully.

It should not claim that the framework is Christian doctrine.

It should be presented as a translation register: a way of exploring how the triadic structure can be spoken within Christian theological language.

## 14. Diagnostic translation

The diagnostic overlay can also be translated into Human Registers.

Canonical Layer 1 diagnostic terms:

- **∿ Slack**
- **≡ Tight**
- **↯ Misdirected**
- **✓ Coherent Formation**

General Layer 2 translations:

| Canonical diagnostic term | Plain-language translation |
|---|---|
| **∿ Slack** | Not enough; underpowered; unsupported; too loose |
| **≡ Tight** | Too much; over-controlled; pressured; rigid |
| **↯ Misdirected** | Aimed wrong; misread; out of alignment; solving the wrong problem |
| **✓ Coherent Formation** | Working well enough; held together; responsive; formed enough to proceed |

Important distinction:

**✓ Coherent Formation** is not a fourth distortion.

It is the well-formed condition.

Human Registers may use warmer phrases such as “healthy emergence,” “working well enough,” “held,” or “responsive,” but the canonical term remains **✓ Coherent Formation**.

## 16. Traceability standard

Every Human Register should include a traceability table.

At minimum, the table should map:

- **⟶ The Three Forces**
- **⬡ The Three Capacities**
- **↻ The Three Operations**
- **∿ Slack**
- **≡ Tight**
- **↯ Misdirected**
- **✓ Coherent Formation**

For more developed registers, the table should also map the 21 Layer 1 components.

Traceability matters because it keeps Layer 2 from becoming a loose collection of metaphors.

## 17. AI-native use

Layer 2 is important for AI-native use because it allows an AI system to choose the right language for the situation.

The same underlying structure can be expressed differently depending on the user’s context.

For example:

| Context | Better register |
|---|---|
| A child is upset | Kid Register |
| A person is planning a workday | Working Register |
| A person is noticing tension or bracing | Embodied Register |
| A person wants general self-reflection | Three Pulls Register |
| A person is exploring theological meaning | Christian Theological Register |

An AI agent using this framework should not always speak in canonical Layer 1 language.

It should choose the Human Register that makes the structure most usable.

---

## 18. Practical use

The simplest Layer 2 question is:

> What language would make the structure usable here?

A more complete Layer 2 process asks:

```text
1. What situation is being interpreted?
2. What audience or domain is this for?
3. Which Human Register fits best?
4. How does the register map back to Layer 1?
5. What practical next move becomes clearer?
```

Layer 2 succeeds when the user does not have to think about the whole architecture in order to benefit from it.

The structure should be present, but not burdensome.

## 22. Working rule

When developing a Human Register, ask:

```text
Who is this language for?
What situation does it help with?
How does it map back to Layer 1?
How does it map back to Layer 0?
Does it make the structure easier to use?
Does it avoid becoming a separate framework?
```

If a register cannot be traced back to **★ Quality**, **● Contact**, **■ Continuity**, and the Layer 1 mechanical systems, it may still be interesting, but it may not belong in the core Human Registers layer.
